### Анализ накопителей аттракционов и подсчёт ограждений

Анализ существующих планов зон ожидания посетителей перед посадкой на аттракцион. Работа выполняется по исходным чертежам, техническому заданию и пожеланиям заказчика, без изменения исходных чертежей.

**Состав работы:**

1. Сопоставление существующей планировки с техническим заданием и пожеланиями заказчика.
2. Анализ разделения потоков обычного и быстрого входа, зон ожидания и общего накопителя перед посадкой.
3. Подсчёт общей длины секций ограждения в погонных метрах с отдельным учётом калиток и проёмов.
4. Подсчёт площадей накопителей обычного и быстрого входа в квадратных метрах по согласованным границам зон.
5. Оформление расчётов и замечаний на отдельном листе по образцу заказчика.

**Ожидаемый результат:** лист с ведомостью ограждений, площадями зон ожидания, пояснениями к подсчётам и перечнем вопросов, требующих уточнения. При недостатке исходных данных неопределённые величины обозначаются отдельно.

Здесь опубликовано только описание вида работ. Чертежи, фотографии, переписка, расчётные файлы и численные результаты не размещаются.

## Устройство сайта

React 19, TypeScript и Vite; Motion для анимаций, Recharts для диаграмм. Шрифт Geist хранится вместе с сайтом. Маршруты с `#` открываются напрямую на GitHub Pages. Серверной базы данных и доступа посетителей к рабочим документам нет.

## Запуск и проверка

Нужны Node.js 24 и pnpm 11.

```sh
pnpm install --frozen-lockfile
pnpm dev
pnpm check
```

Последняя команда проверяет код, запускает тесты, собирает сайт и ищет запрещённые данные в исходных и собранных файлах. Подсказки проверяются на открытие с клавиатуры, повторное нажатие и закрытие. Выгрузка проверяется на ошибки плана и запрещённые поля.

## Откуда берутся данные

1. Локально разрешённые описания хранятся отдельно от рабочих записей, в `09_Public/catalog.json` каждого подключённого проекта.
2. Явная команда выгрузки читает только эти описания, состояния выбранных пунктов плана и состояние проекта. Разрешены проекты `PRJ-001`–`PRJ-004`; новые записи реестра не публикуются автоматически.
3. После проверки структуры и безопасности команда заменяет `src/data/project-manifest.json`. Полные планы, названия внутренних файлов, пути и заметки не копируются.
4. При сборке `scripts/sync-projects.mjs` добавляет общедоступные сведения GitHub в `src/data/generated-projects.json`. При недоступности GitHub остаются разрешённые описания проектов; недоступные сведения об исходном коде не показываются.
5. GitHub Actions проверяет и публикует сайт при изменении основной ветки, по расписанию каждые шесть часов или по ручному запуску.

### Обновление локальных планов

```sh
pnpm export:obsidian --vault "<расположение-хранилища>"
pnpm check
git diff -- src/data/project-manifest.json src/data/generated-projects.json
```

После просмотра изменений их можно сохранить и отправить в публичный репозиторий обычным способом. Выгрузка сама ничего не отправляет. Облачная сборка **не читает локальное хранилище**: расписание обновляет только сведения GitHub, а не рабочие планы на компьютере.

Разрешённое описание имеет поля `publish: true`, `project` и `measure`. В `measure.mode` выбирается `tasks` для отмеченных задач или `milestones` для таблицы этапов; `measure.groups` задаёт публичные названия групп и точные ключи пунктов плана. Неизвестные поля, отсутствующие ключи и противоречивые отметки останавливают всю выгрузку до замены файла.

### Значение показателей

- Выполнение проекта — доля полностью завершённых выбранных пунктов. Незавершённый пункт даёт ноль, все пункты имеют одинаковый вес.
- Это **не оценка физической готовности объекта**, трудозатрат или качества.
- Общее выполнение — среднее по подключённым проектам.
- История содержит только реально сохранённые даты измерений. За один день остаётся последнее значение; прошлые даты не выдумываются. После первого измерения линия ещё не строится.
- Дата проверки планов и дата сборки сайта показаны отдельно.

## Снимки проектов

### Векторные обложки

Карточки используют четыре самостоятельные векторные иллюстрации: композицию кафе, схему праздничных комнат, карту проектной памяти и устройство каталога. Архитектурные изображения явно помечены как условные, без масштаба: это не фактические планировки и не рабочие чертежи. Схема цифрового проекта показывает его назначение и связи. Большая обложка находится на странице каждого проекта; снимки предыдущего вида страниц сохранены ниже с датой.

### Навигация

Шапка закреплена при прокрутке. Меню показывает разделы текущей страницы, выделяет текущий раздел и превращается в раскрываемое меню на узком экране. Прямые ссылки сохраняют раздел в параметре `section` внутри маршрута с `#`; фильтр проектов при этом не сбрасывается. Например: `#/project/cafe-masterskie?section=cover`. Закрыть меню можно кнопкой, клавишей Esc, переходом по ссылке или нажатием вне меню.

Файлы `public/screenshots/*.png` — настоящие снимки публичных страниц, а не изображения внутренних программ, чертежей или документов. Они сохранены на отдельных страницах проектов и открываются в увеличенном виде. Для обновления снимка откройте страницу проекта с `?capture=1` после адреса маршрута: этот режим убирает движение и служебные кнопки. Размер снимка — 1440 × 1000. Дату обновляют в разрешённом описании проекта.

Перед добавлением других изображений нужно проверить их на личные сведения, адреса, пути, закрытые документы и права на публикацию. Проверка текстовых файлов не распознаёт содержимое изображений.

## Границы публикации

Запрещены секреты, ключи доступа, локальные пути, персональные данные и внутренние рабочие документы. Файлы исходного хранилища в этот репозиторий не включаются. Автоматическая проверка дополняет, но не заменяет просмотр разрешённых описаний и снимков перед публикацией.
